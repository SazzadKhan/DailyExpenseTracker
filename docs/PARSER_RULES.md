# XpenseBot Parser — Rules Reference (v3)

Every rule the offline parser applies, in the order it applies them, each with
a real example. **All outputs below were generated by the actual parser**
(`js/features/assistant/parser.js`, default categories, BDT account,
today = 2026-07-13). If you change a rule, re-verify its example against
`tests/extreme-suite.html` — the docs must never promise what the code
doesn't do.

The one law behind every rule: **never guess silently.** A confident answer
must be right; anything uncertain carries `needsReview: true` (shown as ⚠);
anything unreadable lands in `unmatched` instead of becoming an entry.

---

## 1. Normalization (before anything else)

| Rule | Input | Becomes |
|---|---|---|
| Unicode NFC (Bengali composed forms) | any Bengali text | normalized before matching |
| Bengali digits → ASCII | `৫০ rickshaw` | `50 rickshaw` |
| Curated typo fixes (whole words) | `50 riksha 100 got payement` | `50 rickshaw 100 got payment` |
| Spoken number words → digits (English, Banglish, Bengali script; compositional) | `রিকশা ভাড়া পঞ্চাশ টাকা` · `dui hajar taka` · `lunch two hundred fifty` | `… 50 টাকা` · `2000 taka` · `lunch 250` |
| …but a lone small unit stays a word | `one coffee` | unchanged (never amount 1) |
| k-shorthand | `salary 50k` / `coffee 3.5k` | `salary 50000` / `coffee 3500` |

Voice note: bn-BD speech recognition outputs Bengali script and often writes
amounts as words — both are first-class inputs. `টাকা` is detected and
stripped as a currency word like `taka`/`tk`.

The typo map (`TYPOS`) is for misspellings 2+ edits away or that collide with
other vocabulary — `lanch` must become *lunch*, never the *launch* ferry.
One-edit typos don't need entries here; rule 8 catches them.

## 2. Segmentation — where one transaction ends

| Rule | Input | Result |
|---|---|---|
| Newlines, semicolons, commas split | `lunch 150, rickshaw 40` | 2 entries |
| Thousand-separator commas do NOT split | `rent 1,200` | 1 entry, amount 1200 |
| Connectors split when both sides have a number: `and`, typo `nd`, Banglish `ar`/`ebong`, Bengali `এবং`/`আর` | `tea 20 and bus 50` · `cha 15 ar singara 25` | 2 entries each |
| A connector chunk with **no** number merges into its neighbour | `lunch and coffee with client for 450` | **1** entry, 450 |

## 3. Pair-splitting — run-on lines with no separators at all

A segment holding several amounts is split into amount+item groups. The
parser detects the orientation of each group:

| Pattern | Input | Result |
|---|---|---|
| Item-first pairs | `lunch 150 rickshaw 40 tea 20` | 3 entries (150, 40, 20) |
| Amount-first pairs | `50 banna 50 riksha` | banana 50 + rickshaw 50 |
| Orientation flips mid-line | `breakfast 80 100 bus` | breakfast 80 + bus 100 |
| Leading verb skipped for orientation | `spent 500 uber 300 coffee` | uber 500 + coffee 300 |
| Bare amount becomes its own flagged entry | `50 banna 50 riksha 50 100 got payement` | 4 entries; the lone `50` files as Other ⚠ |
| Quantity fusion: small count (≤12) after a verb + bare trailing price = ONE purchase | `bought 2 shirts 1600` · `2 ta shirt 900` | 1 entry, amount 1600 / 900, Shopping › Clothes |
| `at N` is a time, not an amount | `meeting at 3 lunch 400` | 1 entry, lunch 400 |

## 4. Amount extraction

| Rule | Input | Result |
|---|---|---|
| Last real number wins | `iftar party for 40 people 3000` | amount 3000 |
| Numbers followed by a unit word are quantities, not prices (`kg gram litre pc dozen hali packet people jon gula day din hour month km min…`) | `2 kg chal 140` · `dim 4 hali 200` | amount 140 / 200 |
| Leading minus → keep positive amount but flag | `-500 lunch refund` | 500, F&D ⚠ |
| Zero / no number → never an invented entry | `lunch 0` · `hello there` | goes to `unmatched` |

## 5. Dates (extracted before amounts, so `2 days ago` can't become amount 2)

| Grammar | Input | Date |
|---|---|---|
| Literal `YYYY-MM-DD` | `rent 15500 2026-07-01` | 2026-07-01 |
| `N days ago` / Banglish `N din age` | `coffee 60 2 days ago` | today − 2 (amount **60**) |
| `day before yesterday` | `cha 20 day before yesterday` | today − 2 |
| `yesterday` / `gotokal` / `gotkal` / `গতকাল` | `lunch 250 gotokal` · `গতকাল লাঞ্চ ২৫০` | today − 1 |
| `today` / `ajke` / `আজকে` | `bus 40 ajke` | today |
| `last month` — a guess, so flagged | `rent 15000 last month` | same day last month, ⚠ |
| Weekday = most recent occurrence (can be today) | `groceries 900 monday` | last Monday |
| `last <weekday>` = strictly past | `tea 20 last friday` | never today |
| One date word in the message applies to every entry | `lunch 150, rickshaw 40, tea 20 yesterday` | all 3 dated yesterday |
| Future dates accepted but flagged | `dinner 800 on 2027-12-31` | 2027-12-31 ⚠ |
| NOT parsed (by design): month names, "for July", Bengali-script dates | `internet bill 1200 for july` | today; "july" kept in description |

## 6. Classification — first hit wins

Priority order (see PARSER_GUIDE.md for why):

1. **Curated phrase overrides** — `gas bill 800` → Bills & Utilities (not
   vehicle fuel); `pathao food 560` → Delivery (not a ride); `mobile cover` →
   Electronics (not a phone bill).
2. **The user's own category/subcategory names** — bigrams before single
   words, singular/plural folded: `concert ticket 2000` → Entertainment ›
   Concerts/Events.
3. **Learned index** — this user's accepted history (see rule 10). Beats the
   built-in pack: if you've filed "burger" under Delivery twice, `burger 450`
   files under Delivery, not Fast Food.
4. **Synonym pack** — ~300 spoken words in English, Banglish, and Bengali
   script, including the transliterated loanwords bn-BD voice emits
   (`লাঞ্চ`, `সিএনজি`, `ইন্টারনেট`, `রিচার্জ`): `riksha 35` → Public Transit;
   `ডিম ১২০ দুধ ৯০` → two Groceries entries; `daraz 3200` → Online Shopping;
   Bengali bill phrases (`কারেন্ট বিল`, `পানির বিল`) are curated overrides.
5. **Typo tolerance** (rule 8).
6. **Income fallback** — income wording with no category word: `got paid 20k`
   → Income, 20000.
7. **Other ⚠** — honest fallback: `lottery 100` → Other, low confidence,
   flagged. This feeds the learning layer (rule 10).

**Fragment rule:** a single word borrowed from a multi-word *category* name is
weak evidence. `netflix er bill 1100 taka dilam` → Entertainment › Streaming
Services (the word "bill" does not drag it into Bills & Utilities), yet a bare
`bill 500` still reaches Bills & Utilities.

## 7. The income guard

Income needs **explicit income wording** (`salary, received, got paid, earned,
bonus, freelance, sold, beton, pelam, dhukse…`). A lone noun colliding with an
income name never flips the transaction:

| Input | Result |
|---|---|
| `investment 5000` | Other ⚠ (expense reading, flagged — never Income) |
| `birthday gift 800` | Shopping › Gifts ⚠ (collision flagged) |
| `received gift 500` | Income › Gift (intent unlocks it) |
| `beton 20000 pelam` | Income › Salary, 20000 |
| `salary dhukse 30k` | Income › Salary, 30000 |
| `বেতন পেলাম ৩০০০০` | Income › Salary (পেলাম is the receipt verb) |
| `স্কুলের বেতন ২০০০` | flagged ⚠ — বেতন also means school FEES, so bare বেতন is never intent |

**Conflicting signals flag:** income wording around an expense-category word
means the two readings disagree — ask the human. `sold old phone 3500` →
Bills & Utilities › Phone **⚠** (it must never silently file a sale as a
phone bill); `tuition theke 5000 pelam` → flagged the same way.

## 8. Typo tolerance (edit-distance 1)

An unknown Latin word of 5+ letters that is exactly **one edit** from exactly
**one** known vocabulary target adopts that target: `grocarys 850` →
Groceries; `coffe 150` → Coffee & Snacks; `resturant 950` → Restaurants;
`internat bill 900` → Bills › Internet.

Safety valves:
- Two competing targets → no guess.
- A stoplist of common words that must never be "corrected" (`later` is one
  edit from *water*; `saving` is one edit from *shaving*; month names — *march*
  is one edit from *mach*, fish).
- Latin script only; Bengali words match exactly.

## 9. Money-meaning flags (never guesses)

`refund, transfer(red), repay(ment), credit card, borrow(ed), lent, loan,
dhar` force ⚠ — these aren't ordinary spending: `transferred 10000 to
savings` ⚠ · `paid credit card 25000` ⚠ · `borrowed 2000 from friend` ⚠.

Currency conflict also flags: on a BDT account, `lunch $12 and rickshaw 60
taka` → the $12 entry is ⚠, the 60 entry is clean.

## 10. The learning layer (`learned.js`)

| Rule | Meaning |
|---|---|
| 2 accepted entries with the same word = knowledge | Filing "burger" under Delivery twice makes `burger 450` auto-file there |
| 3 *distinct days* of Other-⚠ misses = a suggestion | "bkash" flagged on 3 days → bot offers to create a "Bkash" subcategory; same-day repeats count once (no mid-session nagging) |
| Accepting closes the loop | `bkash 200` then files under Other › Bkash, high confidence, offline |
| Dismissal is permanent | "No thanks" silences that word for good |
| The income guard still applies | A learned income word without income wording stays an expense ⚠ |
